Logo Wall

Component: LogoWall
Props:
  - title (Text)
Collection List:
  - source: Clients collection
  - fields: Name (Text), Logo (Image)
  - the img binds to Logo, the alt binds to Name
Variants:
  - none
Slots:
  - none
Notes:
  - Sits on a LIGHT section in the comps (Bone background) because the
    client logos are dark. The component sets no background of its own.
  - The heading is H4-sized and uses --primary-accent, so it is Moss on a
    light section and Lichen on a dark one.

    to the palette.
  - Only 4 of the 16 marks ship as sample assets; the rest live in the CMS.

Image Marquee

Component: ImageMarquee
Mirrors MAST's "Marquee" component 1:1 (class names match on transfer).
Structure:
  .marquee-component > .marquee-wrapper > .marquee-content > 2x .marquee-group
Settings (custom properties on the root, matching MAST's Style prop):
  --marquee-duration (default 45s)
  --marquee-gap      (default --space-5xl)
Variants:
  - cc-a / cc-b / cc-c on .marquee-item (explicit sizes, never nth-child)
Notes:
  - The SECOND .marquee-group is a duplicate of the first. That is what makes
    the translateX(-50%) loop seamless, and why MAST's component exposes two
    slots tooltipped "add the same set of components in each slot".
  - Full bleed: no .container, so the strip runs past both edges.
  - In Webflow the @keyframes ship in the Custom Code embed (the Marquee toggle
    on the Custom Code component) — the style API cannot write keyframes.
  - Honours prefers-reduced-motion: animation off, strip becomes scrollable.

FAQ Accordion

Component: FaqAccordion
Mirrors MAST's "Accordion" component on class names (rename-free transfer).
Structure (real <details> / <summary>):
  .accordion-component > .accordion-trigger > .accordion-title + .accordion-icon
                       > .accordion-content > .accordion-content_spacer > answer
Collection List: FAQs (6aaef5db7b6168269348044d), sort Order ascending
  .accordion-title -> Name (the question)
  .rich-text       -> Answer (Rich Text)
Notes:
  - STYLING differs from MAST on purpose. MAST draws a full 1px box with the
    card radius and pads the trigger on all sides; the comp is flush — bottom
    rule only, no radius, no horizontal padding. On transfer these become
    COMBOS, not a restyle: MAST's Accordion has 9 instances elsewhere.
  - The icon is a plus, not a chevron, because [open] rotates it 45deg into a
    cross. That rule and the ::-webkit-details-marker reset are runtime state,
    so they live in the CUSTOM CODE CSS EMBED block at the foot of styles.css.
  - Answer must stay Rich Text: one answer contains a bulleted list.
  - Closed by default on the live page; the comp shows them open for review.

Project Thumbnail

Component: ProjectThumbnail
Props:
  - image (Image)        — shown when Vimeo ID is empty
  - vimeoId (Text)       — when set, the video shows and the image hides
  - client (Text)
  - title (Text)
  - link (Link)
Variants (aspect ratio of the asset):
  - base    16:9
  - cc-1x1   1:1
  - cc-9x16  9:16
Slots:
  - none
Vimeo embed URL:
  https://player.vimeo.com/video/<ID>?background=1&autoplay=1&loop=1&muted=1
  background=1 gives a chromeless, autoplaying, looping, muted video.
Notes:
  - THE RATIO TOGGLE MATCHES THE CARD TO THE ASSET. That is why the video
    simply fills the card instead of using a cover trick — pick the ratio
    your source actually is and nothing letterboxes.
  - pointer-events:none on the iframe is load-bearing. Without it the
    embed swallows the mouse and the hover overlay never fires.
  - THE OVERLAY CARRIES THE HOVER, NOT THE CARD. It covers the whole card,
    so hovering the card is hovering the overlay — no Webflow Interaction
    and no banned .card:hover .overlay descendant selector.
  - Labels bind to --color-bone, NOT --primary-text: the scrim is always
    dark, so a themed colour would flip and vanish into it.
  - In Webflow, "video shows / image hides" is CMS CONDITIONAL VISIBILITY
    on the Vimeo ID field — a Designer-only setting, not settable by MCP.
  - Hover has no touch equivalent; below 767px the work grid may want the
    labels always visible.

Video Reel

Component: VideoReel
Props:
  - source (Text)   — hosted video URL
  - poster (Image)
  - label (Text)    — trigger pill copy
Variants: none
Slots:  the dialog body (the full-screen player)
Notes:
  - THE BACKGROUND NEEDS NO JS. It autoplays muted + looping from markup
    attributes. site-scripts/video-reel.js owns ONLY the full-screen
    launch, because a native <dialog> needs showModal().
  - The module holds the play() promise and pauses only once it settles.
    Pausing while play is still pending gets overridden, and audio keeps
    running behind a closed dialog. Verified on all three close paths:
    button, backdrop and Escape.
  - Bleeds past .container to a 20px gutter (comp is 1400 of 1440).
  - In Webflow: MAST's Inline Video (Play on scroll into view = true)
    inside MAST's Modal, whose Slot holds the player. Slot = Designer step.
  - The demo below uses MAST's own placeholder asset so it actually plays.
